# 05-15 输出排障（标准作业文档）

> 适用项目：`dotnet-90days-bootcamp / InprovePlan`
>
> 目标：将一次故障从“现象”沉淀为“可复现、可定位、可修复、可预防”的工程化输出。

---

## 1. 适用范围

- Web API 接口异常（401/403/5xx）
- 依赖不可达（Prometheus/DB/Redis/RabbitMQ）
- 业务规则异常（参数合法但业务不满足）
- 观测异常（日志字段缺失、TraceId 无法串联）

---

## 2. 输出目标（完成定义）

一次排障“完成”必须同时满足：

1. 有故障现象证据（请求与响应）
2. 有日志证据链（请求日志 + 异常日志，可通过 `TraceId` 串联）
3. 有根因定位（文件 + 方法 + 触发条件）
4. 有修复动作（代码或配置）
5. 有回归验证（恢复后同场景通过）
6. 有防回归措施（至少 1 条）

---

## 3. 标准流程（9 步）

## 3.1 故障受理

记录最小事实：

- 时间：
- 接口：
- 请求参数：
- 预期：
- 实际：

## 3.2 证据冻结

在修改前先保留：

- 响应体截图/文本

- 请求日志片段

- 异常日志片段

- 当前关键配置快照

## 3.3 TraceId 串联

从请求响应中的 `traceId` 出发，定位：

- `http.request.started`
- `http.request.completed` / `http.request.failed`
- 对应异常日志 `Error.Code/Type/Message/Stack`

## 3.4 分层归因

先分类，再定责：

- 业务异常：规则不满足
- 系统异常：代码缺陷/未处理异常
- 依赖异常：外部服务不可用/超时
- 观测异常：日志本身不完整或不一致

## 3.5 根因定位

至少输出：

- 文件路径
- 方法名
- 触发条件
- 关键分支/字段

## 3.6 临时止血

优先恢复可用性：

- 回滚配置
- 降级兜底
- 限流或短路策略

## 3.7 永久修复

修改 Prometheus 连接配置,并加入连接服务检测

## 3.8 回归验证

使用同一触发条件重测，确认：

- 响应恢复
- 日志结构正确
- 指标恢复（如 P50/P95）

## 3.9 沉淀输出

形成复盘文档，并登记待办与计划周次。

---

## 4. 证据清单（严格评审）

每个故障至少提供以下证据：

1. 触发请求与响应（失败前）
2. 请求日志（含 `Event/Http/TraceId`）
3. 异常日志（含 `Error.*`）
4. 修复动作（配置前后或 patch）
5. 恢复后请求与响应（成功）
6. 恢复后日志（字段一致）
7. Git 证据（若本地演练不推送，需标明“本地演练”并给本地版本标识）

---

## 5. 质量红线（不通过条件）

出现任一条，评审判不通过：

1. 只给结果，不给证据链
2. 无 `TraceId` 串联
3. 根因仅靠猜测，无定位路径
4. 修复后无回归验证
5. 日志关键字段长期为空（如 `Event/Msg/Error.Code`）
6. 把“无异常日志”直接等同“调用方错误”

## 6.4 根因

- 根因描述：外部服务不可用
- 定位路径：MetricsController/GetP50Async() --> PrometheusQueryService/QueryP50Async() --> PrometheusQuery()
- 触发条件：Prometheus 连接出现失败,失败原因:调用端配置不正确

## 6.5 修复

- 临时止血：接口短路,暂时停止该接口服务
- 永久修复：检查服务配置以及确保服务正常运行
- 关联提交/本地版本：本次故障输出属于测试,不准备上传git仓库

## 6.6 验证

- 失败复现：通过
- 修复验证：通过
- 日志一致性：通过

## 6.7 防回归

- 自动化测试：
  给 PrometheusQueryService 补 3 个用例：
  -- Prometheus 不可达 -> 返回 Success=false
  -- 查询成功但无样本 -> HasData=false
  -- 查询成功有值 -> Success=true && Value!=null

- 启动时服务检查

- 日志字段约束：约定并检查关键字段不可空：Event、TraceId、Error.SourceContext
- 告警规则：5 分钟内 prometheus_http_error 连续出现 N 次报警

---

## 7. 当前项目建议（InprovePlan）

1. 优先保证 `Event/Msg/Error.Code` 非空且语义稳定。
2. `TraceId/SpanId` 统一字符串输出，便于检索。
3. 401 与 403 分开演练，分别保留响应与日志证据。
4. Prometheus 查询失败与无样本窗口要分开返回语义。
5. 复盘文档统一 UTF-8，并固定仓库内相对路径证据引用。

---

## 8. 结论口径

- 通过：证据链完整，根因明确，修复有效，可复用。
- 有条件通过：主链路成立，但缺 1~2 项非阻塞证据。
- 不通过：缺关键证据或根因不成立。
